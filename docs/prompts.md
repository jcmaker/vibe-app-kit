# 에이전트에게 이렇게 말해 보세요

그대로 복사해서 써도 되고, `{ }` 안만 바꿔서 써도 됩니다.
좋은 요청은 대개 이 순서를 따릅니다: **상황 → 내 생각과 이유("왜냐면") → 걱정되는 점 → 부탁 → 답하는 방식**

## 시작할 때

**처음 세팅**
```
이 레포를 처음 써. AGENTS.md를 읽고, 세션 시작 절차대로 세팅해 줘.
내가 해야 하는 일이 있으면 하나씩 알려 줘.
```

**이어서 작업할 때**
```
AGENTS.md랑 docs/HANDOFF.md 읽고, 지금 어디까지 됐는지 세 줄로 알려 줘. 그다음 무엇을 할지 제안해 줘.
```

## 기획 (PRD)

**아이디어를 PRD로**
```
{대충 떠오르는 아이디어 세 줄}
이걸로 PRD를 만들고 싶어. 나는 개발을 몰라. 질문은 한 번에 하나씩, 쉬운 말로 해 줘.
```

**범위 줄이기**
```
PRD에 있는 기능 중에 이번에 꼭 필요한 것과 나중에 해도 되는 것을 나눠 줘. 각각 이유를 한 줄씩.
최대한 빨리 실제로 써 볼 수 있는 상태를 만드는 게 목표야.
```

## 만들기 전

**착수 전 점검**
```
만들기 전에, 내가 꼭 정해야 하는 것과 네가 알아서 정해도 되는 것을 나눠서 보여 줘.
그리고 걱정되는 위험이 있으면 쉬운 말로 알려 줘.
```

**이해했는지 확인**
```
내가 말한 걸 어떻게 이해했는지 네 말로 다시 설명해 줘. 만들기 전에 오해가 없는지 확인하고 싶어.
```

## 만드는 중

**작게 진행**
```
PRD의 {1단계}만 진행해 줘. 끝나면 내가 직접 확인할 방법을 알려 주고 멈춰.
```

**설명 요청**
```
방금 한 걸 개발 모르는 사람한테 설명하듯 알려 줘. 무엇을 바꿨고, 왜 그렇게 했는지.
```

## 확인

**다 했는지 점검**
```
이번 세션에서 하기로 한 것, 전부 했어? 빠진 것과 일부만 한 것을 나눠서 알려 줘. 뺀 게 있으면 이유도.
```

**자신 없는 것만**
```
네가 한 것 중에서 틀렸을 가능성이 높은 것만 골라서 알려 줘. 전부 다 읽게 하지 말고.
```

## 마무리

**저장하고 공유**
```
지금까지 한 걸 커밋하고 PR 만들어 줘. 리뷰하는 사람이 어떻게 확인하면 되는지도 PR에 적어 줘.
```

**인수인계**
```
오늘은 여기까지 할게. docs/HANDOFF.md를 최신으로 고쳐 줘. 다음에 이어서 할 사람이 이것만 읽어도 되게.
```

## 이럴 땐 이렇게

| 상황 | 이렇게 말하기 |
|---|---|
| 질문이 너무 많다 | "네가 추론할 수 있는 건 채우고, 꼭 내가 정해야 하는 것만 물어봐 줘." |
| 말이 너무 어렵다 | "전문 용어 빼고 다시 설명해 줘." |
| 같은 오류가 반복된다 | "멈추고, 지금까지 시도한 것과 막힌 이유를 정리해 줘." |
| 내 의견에 그냥 동의하는 것 같다 | "맞장구치지 말고, 내 생각에 문제가 있으면 솔직하게 말해 줘." |
| 같은 부탁을 세 번째 하고 있다 | "이걸 AGENTS.md에 규칙으로 넣으면 좋을지 제안해 줘." |
